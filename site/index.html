Make Your AI Agent Remember Context Across Sessions

Every AI agent forgets everything when the conversation ends. Agent Memory API is a REST service that gives agents durable memory with semantic recall, automatic expiry, and agent-to-agent permission sharing.

If your agent asks the same onboarding questions every session, or two of your agents need the same customer context but can't see each other's data, this is the gap it fills. Three calls gets you working memory; the rest of this page is everything else you need on one page.

Store and Recall Agent Memory in Under a Minute

The minimum viable integration is two endpoints. Store a fact when your agent learns something; recall relevant facts when a conversation starts.

Python

import httpx

BASE = "https://agent-memory-api.boirama.workers.dev"
HEADERS = {
    "X-RapidAPI-Key": "your-rapidapi-key",
    "X-RapidAPI-Host": "agent-memory-api.p.rapidapi.com",
    "Content-Type": "application/json",
}

# Store what the agent just learned
httpx.post(f"{BASE}/v1/memories", headers=HEADERS, json={
    "content": "User prefers email notifications over SMS",
    "agent_id": "support-bot-001",
    "namespace": "acme-corp/users/preferences",
    "subject_id": "user_8f3kLm92Xn",
    "ttl_seconds": 2592000,   # 30 days
    "importance": 0.85,
})

# Recall it at the start of the next conversation
r = httpx.get(f"{BASE}/v1/memories", headers=HEADERS, params={
    "query": "how does this user want to be contacted",
    "agent_id": "support-bot-001",
    "namespace": "acme-corp/users",
    "limit": 5,
})

for m in r.json()["results"]:
    print(f"{m['score']:.2f}  {m['content']}")

# 0.87  User prefers email notifications over SMS

TypeScript

const BASE = "https://agent-memory-api.boirama.workers.dev";
const headers = {
  "X-RapidAPI-Key": process.env.RAPIDAPI_KEY!,
  "X-RapidAPI-Host": "agent-memory-api.p.rapidapi.com",
  "Content-Type": "application/json",
};

await fetch(`${BASE}/v1/memories`, {
  method: "POST",
  headers,
  body: JSON.stringify({
    content: "User prefers email notifications over SMS",
    agent_id: "support-bot-001",
    namespace: "acme-corp/users/preferences",
    ttl_seconds: 2592000,
  }),
});

const res = await fetch(
  `${BASE}/v1/memories?` + new URLSearchParams({
    query: "how does this user want to be contacted",
    agent_id: "support-bot-001",
    limit: "5",
  }),
  { headers }
);

const { results } = await res.json();
// results[0].content => "User prefers email notifications over SMS"
// results[0].score   => 0.87

Authenticate Your Agent with API Keys

Every request needs authentication. There are two paths depending on how you signed up, and both are complete on this page — you do not need to read another one.

Through RapidAPI (most users)

Send your RapidAPI key on every request. The gateway identifies your account and meters usage; you do not manage keys yourself.

headers = {
    "X-RapidAPI-Key": "your-rapidapi-key",
    "X-RapidAPI-Host": "agent-memory-api.p.rapidapi.com",
}

Direct bearer key (enterprise)

headers = {"Authorization": "Bearer amk_live_your_key_here"}
Keys are server-side credentials. Never ship one in browser JavaScript, a mobile app bundle, or a public repo — anyone holding the key can read every memory in your account.

How Recall Ranking Works

Most memory APIs rank by vector distance alone, which treats every stored fact as equally valuable forever. This one combines three signals:

SignalWeightWhat it measures
Semantic0.55Cosine similarity between the query and the memory
Lexical0.25Postgres full-text match, so exact names and IDs still hit
Salience0.20Importance, decayed by time since last access, reinforced by recall frequency

Salience is the part that matters over time. A fact recalled forty times is load-bearing and gets stronger. A fact nobody has touched in six months fades. Your agent's working set sharpens instead of drowning in stale context. Every result returns its individual sub-scores, so you can see why something ranked where it did.

Handle Errors, Rate Limits and Expiry

StatusMeaningWhat to do
401Missing or unknown keyCheck the header name — it is X-RapidAPI-Key, not Authorization, when going through the gateway
403Bad proxy signatureYou are hitting the origin directly instead of through the gateway
404Memory missing or not visibleIt expired, was deleted, or belongs to an agent that hasn't granted you access
413Content over 8,000 charactersSplit into several memories — recall ranks facts, not documents
422Validation failedRead detail, a flat list of {field, problem}
429Monthly quota exhaustedBack off using Retry-After, or upgrade the plan
import httpx, time

def recall_with_retry(params, attempts=3):
    for attempt in range(attempts):
        r = httpx.get(f"{BASE}/v1/memories", headers=HEADERS, params=params)
        if r.status_code == 429:
            time.sleep(int(r.headers.get("Retry-After", 2 ** attempt)))
            continue
        if r.status_code == 401:
            raise RuntimeError("Check your API key and host header.")
        r.raise_for_status()
        return r.json()["results"]
    return []   # degrade gracefully: an agent with no memory still works
Treat memory as an enhancement, not a dependency. If recall fails, your agent should carry on with an empty context rather than erroring at the user.
